## Requirements

- A recent stable Rust toolchain.
- One of: fish, zsh, or bash 4.4 or newer. (macOS ships bash 3.2, which is not supported.)
- An LLM endpoint that speaks the OpenAI chat API: a hosted one such as [OpenRouter](https://openrouter.ai) or OpenAI, or a server on this machine such as [Ollama](https://ollama.com) or LM Studio.

## Build and set up

<Steps>

1. Build the binary.

   ```sh
   git clone https://github.com/paulomenin/shellmate
   cd shellmate
   cargo build --release
   ```

2. Run guided setup.

   ```sh
   target/release/shellmate setup
   ```

   Setup detects your shell, the hosted services whose key variable is set and the model servers answering on this machine. It lists them, asks you to choose, confirms the connection and asks for the model name. It can also set up an optional checker. It then writes `~/.config/shellmate/config.toml`, adds one block to your shell's rc file and finishes with `shellmate doctor`. It never overwrites an existing config. See [`setup`](../../reference/cli/#setup) for each step.

3. Open a new shell (or reload your rc file) and try it.

   Type `how do I find the biggest files here` and press `alt+m`.

</Steps>

### Non-interactive setup

```sh
shellmate setup --yes --provider openrouter --model "~openai/gpt-luna-latest" --shell fish
```

With `--yes` nothing is asked or contacted, and `--provider` and `--model` are required. Add `--verify` to ask the server for its models first.

Providers known to `setup` and `config init`: `openrouter`, `openai`, `ollama`, `lmstudio`, `localai`, and `custom`. With `custom`, give the base URL of any OpenAI-compatible server (`--base-url`), and where its key is if it needs one (`--api-key env:NAME` or `file:PATH`). A URL on this machine is treated as local, any other as remote. For a remote provider, interactive setup shows what will be sent and asks you to agree. The API key is only ever written as an `env:` or `file:` reference, never as the key itself. To add a checker, pass `--checker`, `--checker-model` and, for `custom`, `--checker-url`.

## What setup changes

Setup writes two things, and only these two:

1. `~/.config/shellmate/config.toml`, a commented starter config.
2. A marked block in your shell's rc file, appended at the end:

   ```sh
   # >>> shellmate >>>
   ...one line that loads the integration, with the absolute path of the binary...
   # <<< shellmate <<<
   ```

The rc file is `~/.config/fish/config.fish`, `${ZDOTDIR:-~}/.zshrc` or `~/.bashrc`. A backup is made once as `<rc file>.shellmate-backup`. Re-running is idempotent: the block is updated in place, for example when the binary path changes.

<Tabs>
	<TabItem label="Preview">
		```sh
		shellmate install-shell --dry-run
		```
	</TabItem>
	<TabItem label="Apply">
		```sh
		shellmate install-shell --yes
		```
	</TabItem>
	<TabItem label="Remove">
		```sh
		shellmate install-shell --remove
		```
	</TabItem>
</Tabs>

Without a terminal, `install-shell` refuses to change anything unless you pass `--yes`.

## Check the installation

```sh
shellmate doctor
```

Each check prints `OK`, `WARN` or `FAIL`, and every non-OK line says how to fix it. `doctor` exits with status 1 only when something FAILs. `--json` gives machine-readable output. See [Troubleshooting](../../guides/troubleshooting/).

## Manual installation

If you prefer to edit your rc file yourself, add one line with the absolute path of the binary:

<Tabs>
	<TabItem label="fish">
		```fish
		# ~/.config/fish/config.fish
		/path/to/shellmate init fish | source
		```
	</TabItem>
	<TabItem label="zsh">
		```zsh
		# ~/.zshrc
		source <(/path/to/shellmate init zsh)
		```
	</TabItem>
	<TabItem label="bash">
		```bash
		# ~/.bashrc, at the END (after prompt tools such as starship)
		eval "$(/path/to/shellmate init bash)"
		```
	</TabItem>
</Tabs>
